# 레벨 폭발 모험단 — 20단계 개발 계획 (오퍼스 5.5 로컬 Studio 세션용)

> 목적: `balance/BOSS20_BALANCE_DESIGN.md` 의 설계를 **한 번에** 구현하지 않고, 비슷한 작업량의 20단계로 나눠 단계마다 개발자가 직접 플레이하며 밸런스를 맞춘다.
> 순서: 게임 틀(1~5) → 초반(6~9) → 초중반(10~12) → 중반(13~15) → 중말(16~17) → 말기(18~20).
> 각 단계 = ①목표 ②범위(설계서·config 키) ③끝났을 때 보이는 것 ④내가 점검할 것(기대값은 300판 시뮬, 허용 범위 포함) ⑤안 맞으면 돌릴 노브 ⑥오퍼스 세션에 붙여넣을 프롬프트.
> 단계 하나 = 오퍼스 세션 1~2회 분량. 18·19는 보스 5마리라 무거우니 필요하면 "1~3구간 / 4~5구간" 두 세션으로 쪼갠다.

---
## 공통 규칙 (모든 프롬프트 맨 위에 붙임)

```
Roblox Studio 에서 내 게임 "레벨 폭발 모험단"을 이어서 만들어 줘.
수치의 단 하나의 원본은 ReplicatedStorage.BalanceConfig (레포 balance/boss20_config.json 을 그대로 옮긴 ModuleScript) 다.
코드에 숫자를 하드코딩하지 말고 전부 BalanceConfig 에서 읽어라. 키 이름은 JSON 과 똑같이(snake_case).
규칙: 아주 쉬운 한국어, 바꾸기 전 백업, 로벅스 뽑기·치장 상품 금지, 서버 권한(데미지·경험치·드롭 계산은 서버),
자잘한 글자 알림 금지(이펙트·소리로), 끝나면 Ctrl+S → Publish 알려 주고 "내가 점검할 것" 목록을 그대로 출력해 줘.
디버그 HUD(F3 토글): 레벨·포인트·체력/공격/행운/흡혈·DPS·공속 배율·흡혈률·초당 회복 상한·에너지·사망 횟수·보스 체력바/장갑 상한 표시.
```

점검 방법 공통: 디버그 HUD 숫자를 설계서 표와 비교한다. 기대값은 시뮬 중간값이고 "허용"은 ±로 적힌 범위. 10판 정도 돌려 평균이 범위 안이면 통과. 벗어나면 그 단계의 노브만 돌리고 다음 단계로 넘어가지 않는다(앞 단계 수치가 뒤 단계 앵커를 결정하기 때문).

# 1부. 게임 틀 (1~5단계) — 몬스터 1종·보스 1마리로 "숫자가 맞는지"만 본다

## 1단계. 수치 뼈대: BalanceConfig + 경험치 곡선 + 레벨·포인트·능력치
- 목표: JSON 을 그대로 모듈로 옮기고, 레벨·경험치·포인트·자동 분배·능력치 공식이 설계서 §2·§3 과 1:1 로 맞게.
- 범위: `exp_curve`(need/E/L 닫힌 식 3개, 레벨만 저장), `stats`(기본 100/10/1/0, 포인트당 +10/+2/+1/+1), 레벨당 포인트 3, 자동 분배 기본 비율 1:2:0.5:0.5 + 프리셋 5종(`builds`), 흡혈 포화식, 치명 식, '행운!' 2배 당첨(p 식, 상한 ×1.5). 전투·몬스터는 아직 없음 — 디버그 명령으로 경험치를 넣어 본다.
- 끝났을 때: 디버그 명령 `/exp N` 으로 경험치를 넣으면 레벨·포인트·능력치가 오르고 HUD 에 보인다.
- 내가 점검할 것:
  - `/exp 1005` → 레벨 100, `/exp 309500` 추가 → 레벨 100,000 (§3.2 표).
  - 레벨 1,000 균형 분배(당첨 끄고): 체력 7,592 / 공격력 3,007 / 행운 376 (§2.1 예시).
  - 레벨 1,000 치명 29.6%, 흡혈 7.9%(장비 없음).
  - 당첨 켜고 레벨 1,000 까지 100번 반복 평균 포인트 ≈ 3,000 × 1.20 (허용 1.15~1.25).
  - 레벨 1억·100억에서도 숫자가 깨지지 않음(만/억/조 축약 표시).
- 안 맞으면: `exp_curve.a`(0.3), `formulas.crit.*`, `formulas.lifesteal.*`, `formulas.luck_bonus.p_coef/p_cap`.
- 프롬프트:
```
[공통 규칙]
1단계: 수치 뼈대만 만든다. balance/boss20_config.json 을 ReplicatedStorage.BalanceConfig 로 옮기고(키 그대로),
경험치 곡선 need(L)=10×(1+L/1000)^0.3, E(L), L(E) 닫힌 식 3개를 ExpCurve 모듈로. 서버는 레벨만 저장하고 획득 시 L(E(L)+Δ) 로 복원.
레벨당 포인트 3 + '행운!' 2배 당첨(p=min(0.5, 0.5×행운/(행운+0.5×레벨+50))). 자동 분배 비율(기본 1:2:0.5:0.5, 프리셋 5종)과 수동 찍기 버튼.
능력치: 체력 100+10pt, 공격 10+2pt, 행운 1+pt, 흡혈률 = min(30%, 30%×P/(P+레벨+50)), 치명 = min(60%, 5%+60%×행운/(행운+0.5×레벨+40)).
디버그 명령 /exp N, /lvl N, /reset. 디버그 HUD. 몬스터·전투는 아직 만들지 마.
끝나면 "내가 점검할 것" 5개를 출력해 줘.
```

## 2단계. 전투 코어 (펭귄 1종으로)
- 목표: 때리고 맞는 규칙이 설계서 §2.2·§2.4 와 같게. 몬스터는 펭귄 1종만.
- 범위: 자동 타격·버튼 평타 1.0초 쿨다운 공유, 피해 = 공격력×U(0.9,1.1)×치명(×2.0), 몬스터 예고 0.45초 후 판정, 받는 피해 = 공격×U(0.9,1.1), 한 타 ≤ 최대 체력 75%, 흡혈 초당 상한 max(5%, 0.8×흡혈률)(스윙당 = 상한×간격), 전투 종료 회복 50%, 비전투 6%/초, 레벨업 회복, 사망 = 그 자리 부활·2.5초 무적·적 체력 유지. 펭귄(체력 30·공격 12·간격 1.3·경험치 300).
- 끝났을 때: 광장에서 /spawn penguin 으로 펭귄을 불러 싸울 수 있다.
- 내가 점검할 것:
  - 레벨 1 펭귄: 3타에 죽고(허용 3~4), 9타를 버틴다(허용 8~10). 1마리 뒤 레벨 30(300 경험치).
  - 펭귄 3마리 연속 뒤 레벨 89(허용 85~92).
  - HUD 의 DPS ≈ 공격력 × 1.0(치명 포함 ×1.05 안팎).
  - 흡혈 50%를 디버그로 강제해도 초당 회복이 최대 체력의 20%를 넘지 않음.
  - 사망 후 부활하면 펭귄 체력이 그대로.
- 안 맞으면: `combat.base_cooldown_s`(1.0), `formulas.damage_taken.player_hit_cap`(0.75), `formulas.lifesteal.heal_per_s_cap_base`.
- 프롬프트:
```
[공통 규칙]
2단계: 전투 코어. 몬스터는 펭귄 1종(monsters.penguin)만. 자동 타격(사거리 9)과 버튼 평타(사거리 11)는 1.0초 쿨다운을 공유.
피해·치명·받는 피해·한 타 75% 상한·흡혈 초당 상한(max(5%, 0.8×흡혈률)×최대체력, 스윙당 = 상한×공격 간격)·전투 종료 50% 회복·비전투 6%/초·레벨업 회복(늘어난 최대 체력만큼)을
전부 BalanceConfig.formulas 에서 읽어 구현. 사망: 그 자리 부활·체력 가득·2.5초 무적·적 체력 유지. 몬스터 공격은 거리 3.2+반지름, 0.45초 예고(빨간 번쩍) 후 판정, 등장 뒤 첫 공격 1.2초.
/spawn penguin N 디버그 명령. 데미지 숫자 팝(치명은 크게). 끝나면 "내가 점검할 것" 출력.
```

## 3단계. 판 구조: 에너지·조우·구간·문·결산
- 목표: 마을 → 갈림길 광장 → 가운데 1구간(Z −120~−385) 한 판이 돈다.
- 범위: 에너지 16, 전투 −1, 누진 사망 3→4→5→6(광장에서 초기화), 보스 +4(보스는 아직 없으니 제단 터치 = +4 임시), 조우 게이지(25 stud/칸, 3칸부터 매초 칸수×15%), 마릿수 1/2/3 = 35/45/20%, 인트로 펭귄 3전 고정, 도박 구역(반지름 10, 구간 3곳, 경험치 ×2·피해 ×1.5·1회 소진), 문(이번 판 처치), 판 종료 결산 카드, 저장(장비·기록만, 레벨 초기화).
- 끝났을 때: 마을에서 나가 펭귄만 나오는 1구간을 끝까지 걷고 에너지가 0 이 되면 결산이 뜬다.
- 내가 점검할 것:
  - 1구간에서 전투 4번 안팎(허용 3~5)으로 제단 도착.
  - 마을 문 → 제단 약 14초(걷기 20 stud/초).
  - 사망 4번 연속 시 에너지 −3,−4,−5,−6 순서.
  - 도박 구역 전투는 경험치 2배, 같은 구역 두 번째는 보너스 없음.
  - 결산 뒤 레벨 1·포인트 0, 최고 기록은 남음.
- 안 맞으면: `run.encounter.stud_per_bar`(25), `run.energy_*`, `combat.zone_*`.
- 프롬프트:
```
[공통 규칙]
3단계: 판 구조. run 블록(에너지 16, 전투 −1, 사망 누진 3/4/5/6 + 광장 초기화, 보스 +4)과 조우 게이지(25 stud/칸, 3칸부터 매초 칸수×15%, 마릿수 35/45/20%),
가운데 1구간 Z −120~−385(설계서 §4.3), 인트로 펭귄 3전 고정, 도박 구역 3곳(반지름 10, 경험치 ×2·피해 ×1.5, 1회 소진 표시), 제단(임시: 터치하면 에너지 +4·문 열림),
판 종료 결산 카드(최종 레벨·처치 보스·사망·니어미스), DataStore 저장(장비·기록 유지, 레벨·포인트·에너지 초기화). 끝나면 "내가 점검할 것" 출력.
```

## 4단계. 장비 프레임 (아이템은 엄니검 1개)
- 목표: 7칸·효과 키 집계·상한표·제단 앞 교체 UI 가 동작. 아이템은 엄니검만.
- 범위: `slots`(무기1·정령1·반지2·망토1·왕관1·부적1), `items[].effects` 의 {k, v, up} 집계 함수(설계서 §7.1 효과 키 28종 — 지금은 atk_mult_bonus 만 쓰지만 함수는 전부), `caps.pve` 16항목, 자동 장착(rank), 가방·제단 앞 교체, 엄니검(공격 ×1.35) 드롭은 디버그 `/give I01`.
- 끝났을 때: 엄니검을 끼면 HUD 공격력이 ×1.35.
- 내가 점검할 것:
  - 레벨 1,000 균형: 공격력 3,007 → 엄니검 4,059(허용 ±1%).
  - 디버그로 atk_mult_bonus 를 5.0 넣어도 배율 3.5 에서 멈춤(상한).
  - 제단 앞에서 빼고 끼기가 에너지 소모 없이 됨. 판 끝나도 장착 상태 유지.
- 안 맞으면: `caps.pve.*`, `items.I01.effects`.
- 프롬프트:
```
[공통 규칙]
4단계: 장비 프레임. slots(7칸), items 의 effects {k,v,up} 를 모두 더하는 aggregate 함수(설계서 §7.1 효과 키 사전 28종 전부 지원, 곱/합/상한 규칙 그대로),
caps.pve 16항목 적용, 자동 장착(rank 높은 것), 가방 UI·제단 앞 교체(에너지 소모 없음), /give I01 디버그. 엄니검 = 공격 배율 +0.35.
강화 수치(1.08^p)는 자리만 만들고 UI 는 9단계에서. 끝나면 "내가 점검할 것" 출력.
```

## 5단계. 보스 코어 + B01 수정 매머드
- 목표: 체력바·전환 무적·장갑·관통·그로기가 돌고, 첫 보스가 장비 없이 잡힌다.
- 범위: 보스 공통(체력바 N개, 전환 무적, 장갑 hit_cap × 관통(치명 ×1.5), 그로기 중 ×2, 보스 간격·첫 공격 0.8초, 제단 입장 체력 가득, 제단 반지름 9 안 1.4초 뒤 등장), 기믹 원시형 1개(그로기: 10초마다 3초·피해 ×1.5·상한 ×2), B01(체력 16,200·공격 258·간격 2.1·체력바 3·전환 1.5초·장갑 3.5%·경험치 3,600·드롭 엄니검·1급 강화석 2), 문 열림 4초 연출.
- 끝났을 때: 1구간 끝에서 수정 매머드와 싸우고 잡으면 엄니검이 나온다.
- 내가 점검할 것(장비 0, 10판):
  - 1보스 도착 레벨 중간 154(허용 120~200).
  - 승률 100%, 보스전 25초(허용 20~38), 사망 평균 0.5(허용 0.2~1.0).
  - 한 타가 보스 체력의 3.5% 를 넘지 않음(최소 29타). '한계!' 표기.
  - 그로기 중 숫자가 노랗게 1.5배.
  - 첫 판 전체 3.2분(허용 2.5~4.5), 2보스 제단은 아직 없으니 1보스 뒤 에너지로 1구간을 더 돌다 끝남.
- 안 맞으면: `bosses.B01.hp/atk/hit_cap`, `bosses.B01.gimmick.groggy`, 사망이 많으면 `atk` −10%.
- 프롬프트:
```
[공통 규칙]
5단계: 보스 코어 + B01. BossCore: phases(체력바), transition_s(전환 무적, 화면 정지), hit_cap(1타 ≤ 최대 체력×hit_cap×관통, 치명 관통 1.5, 상한 2.0, 그로기 ×2),
보스 간격·전환 뒤 첫 공격 0.8초, 제단 입장 시 체력 가득, 제단 반지름 9 안 1.4초 뒤 솟아오름. 기믹 원시형은 groggy 만(10초마다 3초, 피해 ×1.5).
B01 수정 매머드 = bosses.B01 그대로(Mount10 수정 재질, 키 8). 처치: 에너지 +4, 문 4초 연출, 첫 처치 엄니검 + 1급 강화석 2 드롭, 재처치 강화석 1(25%로 +1, 무사망 +1).
'한계!' 표기(상한 타격). 끝나면 "내가 점검할 것" 출력.
```

# 2부. 초반 (6~9단계) — 가운데 1~3구간

## 6단계. 1구간 완성: 젤리말·불늑대 + 레벨 티커
- 범위: monsters jelly(536/82/450)·firewolf(953/123/1.1초/rush 19)·펭귄 가중치 45/35/20, rush 등장(60 stud 밖 3초 ×1.5), 1:N 전투(2~3마리, 0.3초 어긋난 공격), 레벨 티커 0.8초 롤링 + 자릿수 피치, 행운! 팝(고레벨 묶음).
