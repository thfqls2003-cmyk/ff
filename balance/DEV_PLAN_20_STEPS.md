# 레벨 폭발 모험단 — 20단계 개발 계획 (오퍼스 5.5 로컬 Studio 세션용)

> 목적: `balance/BOSS20_BALANCE_DESIGN.md` 의 설계를 **한 번에** 구현하지 않고, 비슷한 작업량의 20단계로 나눠 단계마다 개발자가 직접 플레이하며 밸런스를 맞춘다.
> 순서: 게임 틀(1~5) → 초반(6~9) → 초중반(10~12) → 중반(13~15) → 중말(16~17) → 말기(18~20).
> 각 단계 = ①목표 ②범위(설계서·config 키) ③끝났을 때 보이는 것 ④내가 점검할 것(기대값은 300판 시뮬, 허용 범위 포함) ⑤안 맞으면 돌릴 노브 ⑥오퍼스 세션에 붙여넣을 프롬프트.
> 단계 하나 = 오퍼스 세션 1~2회 분량. 18·19는 보스 5마리라 무거우니 필요하면 "1~3구간 / 4~5구간" 두 세션으로 쪼갠다.
> **기준 수치 = 설계서 v1.2**(`balance/BOSS20_BALANCE_DESIGN.md`, `SIM_RESULT.txt` 300판). v1.1 과 달라진 규칙: 조우 = 고정 트리거(확률 게이지 폐기), 사망 카운터는 문마다 초기화, 에너지 상한 30, 에너지 0 = 마지막 도전, 마지막 보스 뒤 자동 결산, 보스전 제단 가두기, rise 몬스터 이속 22, 인트로 펭귄→펭귄→젤리말, B01 보상 2택1(엄니검/수정 갑주), 누적 경험치 E 저장, 행운! 이항 1회 추첨, 패스 = 30일 개발자 상품. 출시 분할은 4차: **1차 MVP = 11단계까지(가운데 1~5구간)**, 2차 = 17단계까지, 3차 = 18단계, 4차 = 19~20단계.

## 공통 규칙 (모든 프롬프트 맨 위에 붙임)

```

수치의 단 하나의 원본은 ReplicatedStorage.BalanceConfig (레포 balance/boss20_config.json 을 그대로 옮긴 ModuleScript) 다.
코드에 숫자를 하드코딩하지 말고 전부 BalanceConfig 에서 읽어라. 키 이름은 JSON 과 똑같이(snake_case).
규칙: 아주 쉬운 한국어, 바꾸기 전 백업, 로벅스 뽑기·치장 상품 금지, 서버 권한(데미지·경험치·드롭 계산은 서버),
자잘한 글자 알림 금지(이펙트·소리로), 끝나면 Ctrl+S → Publish 알려 주고 "내가 점검할 것" 목록을 그대로 출력해 줘.
전투 규칙은 (플레이어 상태·적 목록·시드) → 이벤트 로그를 내는 순수 ModuleScript(CombatCore)로 만들고 월드는 그 결과를 보여 주기만 해라(자동 모험·예측 카드·PvP 가 같은 모듈을 쓴다).
전투 상태(체력·쿨다운·콤보·에너지·사망 카운터)는 전부 서버. 이동은 서버가 속도 검증(틱당 이동 > 이속×1.3 이면 되돌림).
디버그 HUD(F3 토글): 레벨·포인트·체력/공격/행운/흡혈·DPS·공속 배율·흡혈률·초당 회복 상한·에너지·남은 목숨·사망 횟수·보스 체력바/장갑 상한 표시.
```

점검 방법 공통: 디버그 HUD 숫자를 설계서 표와 비교한다. 기대값은 시뮬 중간값이고 "허용"은 ±로 적힌 범위. 10판 정도 돌려 평균이 범위 안이면 통과. 벗어나면 그 단계의 노브만 돌리고 다음 단계로 넘어가지 않는다(앞 단계 수치가 뒤 단계 앵커를 결정하기 때문).

# 1부. 게임 틀 (1~5단계) — 몬스터 1종·보스 1마리로 "숫자가 맞는지"만 본다

## 1단계. 수치 뼈대: BalanceConfig + 경험치 곡선 + 레벨·포인트·능력치
- 목표: JSON 을 그대로 모듈로 옮기고, 레벨·경험치·포인트·자동 분배·능력치 공식이 설계서 §2·§3 과 1:1 로 맞게.
- 범위: `exp_curve`(need/E/L 닫힌 식 3개, **누적 경험치 E(double) 를 저장**하고 레벨 = floor(L(E)+1e-9) 캐시·단조 보호 — 레벨만 저장하면 왕복 −1 버그), `stats`(기본 100/10/1/0, 포인트당 +10/+2/+1/+1), 레벨당 포인트 3, 자동 분배 기본 비율 1:2:0.5:0.5 + 프리셋 5종(`builds`), 흡혈 포화식, 치명 식, '행운!' 2배 당첨 = 레벨이 n 오를 때 Binomial(n, p) **1회 추첨**(n<50 직접 주사위, 그 이상 정규 근사 — 레벨마다 루프 금지, 상한 ×1.5). 전투·몬스터는 아직 없음 — 디버그 명령으로 경험치를 넣어 본다.
- 끝났을 때: 디버그 명령 `/exp N` 으로 경험치를 넣으면 레벨·포인트·능력치가 오르고 HUD 에 보인다.
- 내가 점검할 것:
  - `/exp 1005` → 레벨 100, `/exp 309500` 추가 → 레벨 100,000 (§3.2 표).
  - 레벨 1,000 균형 분배(당첨 끄고): 체력 7,592 / 공격력 3,007 / 행운 376 (§2.1 예시).
  - 레벨 1,000 치명 29.6%, 흡혈 7.9%(장비 없음).
  - 당첨 켜고 레벨 1,000 까지 100번 반복 평균 포인트 ≈ 3,000 × 1.20 (허용 1.15~1.25).
  - 레벨 1억·100억에서도 숫자가 깨지지 않음(만/억/조 축약 표시). `/exp` 로 1~19,999 레벨을 전수 왕복해도 레벨이 1 깎이는 일이 없음(E 저장 확인).
  - `/exp 5580000000000`(B20 경험치 한 방) 을 넣어도 멈춤 없이 1프레임 안에 처리(이항 1회 추첨 확인).
- 안 맞으면: `exp_curve.a`(0.3), `formulas.crit.*`, `formulas.lifesteal.*`, `formulas.luck_bonus.p_coef/p_cap`.
- 프롬프트:
```
[공통 규칙]
1단계: 수치 뼈대만 만든다. balance/boss20_config.json 을 ReplicatedStorage.BalanceConfig 로 옮기고(키 그대로),
경험치 곡선 need(L)=10×(1+L/1000)^0.3, E(L), L(E) 닫힌 식 3개를 ExpCurve 모듈로. 서버는 누적 경험치 E(double)를 저장 원본으로 두고 레벨 = floor(L(E)+1e-9) 캐시(단조 보호, 레벨만 저장 금지).
레벨당 포인트 3 + '행운!' 2배 당첨(p=min(0.5, 0.5×행운/(행운+0.5×레벨+50))) — 레벨이 n 오르면 Binomial(n,p) 를 1회만 추첨(n<50 직접, 그 이상 정규 근사 n·p+√(n·p·(1−p))·Z). 레벨마다 루프 돌지 마. 자동 분배 비율(기본 1:2:0.5:0.5, 프리셋 5종)과 수동 찍기 버튼.
능력치: 체력 100+10pt, 공격 10+2pt, 행운 1+pt, 흡혈률 = min(30%, 30%×P/(P+레벨+50)), 치명 = min(60%, 5%+60%×행운/(행운+0.5×레벨+40)).
디버그 명령 /exp N, /lvl N, /reset. 디버그 HUD. 몬스터·전투는 아직 만들지 마.
끝나면 "내가 점검할 것" 5개를 출력해 줘.
```

## 2단계. 전투 코어 (펭귄 1종으로)
- 목표: 때리고 맞는 규칙이 설계서 §2.2·§2.4 와 같게. 몬스터는 펭귄 1종만.
- 범위: 자동 타격·버튼 평타 1.0초 쿨다운 공유, 피해 = 공격력×U(0.9,1.1)×치명(×2.0), 몬스터 예고 0.45초 후 판정, 받는 피해 = 공격×U(0.9,1.1), 한 타 ≤ 최대 체력 75%, 흡혈 초당 상한 max(5%, 0.8×흡혈률)(스윙당 = 상한×간격), 공속 실효 절대 상한 ×2.2, 전투 종료 회복 50%, 비전투 6%/초, 레벨업 회복, 사망 = 그 자리 부활·2.5초 무적·적 체력 유지. 펭귄(체력 30·공격 12·간격 1.3·경험치 300·이속 22 — 플레이어 20 보다 빨라 뒤로 걷기로 떨어뜨릴 수 없음).
- 끝났을 때: 광장에서 /spawn penguin 으로 펭귄을 불러 싸울 수 있다.
- 내가 점검할 것:
  - 레벨 1 펭귄: 3타에 죽고(허용 3~4), 9타를 버틴다(허용 8~10). 1마리 뒤 레벨 30(300 경험치).
  - 펭귄 3마리 연속 뒤 레벨 89(허용 85~92).
  - HUD 의 DPS ≈ 공격력 × 1.0(치명 포함 ×1.05 안팎).
  - 흡혈 50%를 디버그로 강제해도 초당 회복이 최대 체력의 20%를 넘지 않음.
  - 사망 후 부활하면 펭귄 체력이 그대로.
  - 뒤로 걸어도 펭귄(이속 22)이 따라붙어 공격이 들어옴(카이팅 불가).
- 안 맞으면: `combat.base_cooldown_s`(1.0), `formulas.damage_taken.player_hit_cap`(0.75), `formulas.lifesteal.heal_per_s_cap_base`.
- 프롬프트:
```
[공통 규칙]
2단계: 전투 코어. 몬스터는 펭귄 1종(monsters.penguin)만. 자동 타격(사거리 9)과 버튼 평타(사거리 11)는 1.0초 쿨다운을 공유.
피해·치명·받는 피해·한 타 75% 상한·흡혈 초당 상한(max(5%, 0.8×흡혈률)×최대체력, 스윙당 = 상한×공격 간격)·전투 종료 50% 회복·비전투 6%/초·레벨업 회복(늘어난 최대 체력만큼)을
전부 BalanceConfig.formulas 에서 읽어 구현(CombatCore 순수 모듈 + 월드 투영). 사망: 그 자리 부활·체력 가득·2.5초 무적·적 체력 유지. 몬스터 공격은 거리 3.2+반지름, 0.45초 예고(빨간 번쩍) 후 판정, 등장 뒤 첫 공격 1.2초, 이속은 monsters.speed(펭귄 22).
/spawn penguin N 디버그 명령. 데미지 숫자 팝(치명은 크게). 끝나면 "내가 점검할 것" 출력.
```

## 3단계. 판 구조: 에너지·조우·구간·문·결산
- 목표: 마을 → 갈림길 광장 → 가운데 1구간(Z −120~−385) 한 판이 돈다.
- 범위: 에너지 16·보유 상한 30, 전투 −1, 누진 사망 3→4→5→6(**문(보스 처치)마다 초기화** — 광장 왕복으로는 초기화 안 됨), 보스 +4(보스는 아직 없으니 제단 터치 = +4 임시), **조우 = 고정 트리거**(구간 길이 ÷ 4 지점마다 ±10 stud 지터, 확률 게이지 없음), 마릿수 1/2/3 = 35/45/20%(1구간은 100/0/0), 인트로 펭귄 3전 고정(6단계에서 3번째를 젤리말로 교체), 도박 구역(반지름 10, **구간당 1곳** 트리거 위·인트로 제외, 경험치 ×2·피해 ×1.5 — 1구간은 ×1.0·2구간 ×1.2, 1회 소진), **에너지 0 = 마지막 도전**(남은 트리거 OFF, 제단 보스전만, 사망하면 종료), 처치한 구간 트리거 OFF, 문(이번 판 처치), 판 종료 결산 카드, HUD '남은 목숨 ♥', 저장(장비·기록만, 레벨 초기화).
- 끝났을 때: 마을에서 나가 펭귄만 나오는 1구간을 끝까지 걷고 에너지가 0 이 되면 결산이 뜬다.
- 내가 점검할 것:
  - 1구간에서 전투 **정확히 4번**(인트로 3 + 트리거 1)으로 제단 도착 — 빨리 달려도 느리게 걸어도 같다.
  - 마을 문 → 제단 약 14초(걷기 20 stud/초).
  - 사망 4번 연속 시 에너지 −3,−4,−5,−6 순서. 제단 터치(+4) 뒤 다시 죽으면 −3 부터.
  - 에너지 0 이 되면 상단에 '마지막 도전' 표시, 남은 트리거는 생기지 않고 제단만 남음.
  - 도박 구역은 1구간에 1곳(인트로 제외), 그 전투는 경험치 2배(1구간은 피해 ×1.0), 두 번째는 보너스 없음.
  - 결산 뒤 레벨 1·포인트 0, 최고 기록은 남음.
- 안 맞으면: `run.encounter.jitter_stud`(10), `routes.main.stages[].fights`(4), `run.energy_*`, `run.death_counter_reset`('door'), `combat.zones_per_stage`(1).
- 프롬프트:
```
[공통 규칙]
3단계: 판 구조. run 블록(에너지 16·상한 30, 전투 −1, 사망 누진 3/4/5/6 — 카운터는 문(보스 처치)마다 0, 보스 +4, last_stand: 에너지 0 이면 남은 조우 없이 제단 보스전만·사망 시 종료)과
조우 고정 트리거(run.encounter: 구간 길이 ÷ stages[].fights 지점마다 ±10 stud 지터로 전투 1회 강제, 처치한 구간은 OFF, 마릿수 2구간부터 35/45/20%),
가운데 1구간 Z −120~−385(설계서 §4.3), 인트로 펭귄 3전 고정(구역 없음), 도박 구역 1곳(트리거 위, 반지름 10, 경험치 ×2·피해 ×1.0(1구간), 1회 소진 표시, 붉은 테두리), 제단(임시: 터치하면 에너지 +4·문 열림),
HUD '남은 목숨 ♥'(지금 에너지로 감당 가능한 사망 수), 판 종료 결산 카드(최종 레벨·처치 보스·사망·니어미스), DataStore 저장 v2(장비·기록 유지, 레벨·포인트·에너지 초기화). 끝나면 "내가 점검할 것" 출력.
```

## 4단계. 장비 프레임 (아이템은 엄니검 1개)
- 목표: 7칸·효과 키 집계·상한표·제단 앞 교체 UI 가 동작. 아이템은 엄니검만.
- 범위: `slots`(무기1·정령1·반지2·망토1·왕관1·부적1), `items[].effects` 의 {k, v, up} 집계 함수(설계서 §7.1 효과 키 28종 — 지금은 atk_mult_bonus·dmg_reduce·range_add 만 쓰지만 함수는 전부), `caps.pve` 16항목, 자동 장착(rank), 가방·제단 앞 교체, 엄니검(공격 ×1.35, I01)과 수정 갑주(피해 −10%·범위 +3, I00, 강화 불가) 드롭은 디버그 `/give I01`, `/give I00`.
- 끝났을 때: 엄니검을 끼면 HUD 공격력이 ×1.35.
- 내가 점검할 것:
  - 레벨 1,000 균형: 공격력 3,007 → 엄니검 4,059(허용 ±1%).
